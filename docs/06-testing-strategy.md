# Testing Strategy

Goal: catch defects before users do, and make regressions impossible to merge. CI blocks merge on any failure.

## 1. Test pyramid

| Level | Tooling | Scope | Target |
|---|---|---|---|
| Unit | Vitest | `domain`, `contracts`, utilities, hooks | 80%+ lines/branches on domain and contracts; 100% of formulas/state machines |
| Property-based | fast-check | Pricing, cost allocation, unit conversion, sync merge, ledger math | Invariants hold for random inputs |
| Component | Vitest + Testing Library + Storybook interaction tests | `ui` components, all states | Each component: default, loading, empty, error, disabled, RTL |
| API integration | Vitest/Jest + Supertest on **real Postgres + Redis** (Testcontainers) | Every endpoint: success, validation errors, permission denied, tenancy, idempotency | Every route has >= 1 happy and 1 denial test |
| Tenant-leak suite | Generated per table | User A can read/update/delete zero rows of farm B, including via joins and composite FK tricks | 100% of tenant tables |
| Contract tests | OpenAPI diff in CI | No breaking API change without version bump; mobile min-version honored | |
| E2E web | Playwright | Core flows in en and ur (RTL), light/dark | Critical flows below |
| E2E mobile | Maestro (or Detox) | Login, milk entry offline, sync, scan | Critical mobile flows |
| Sync tests | Custom harness | Offline edits, two devices, clock skew, interrupted sync, token expiry | See docs/09 matrix |
| Visual regression | Storybook + Playwright screenshots | Components in light/dark, LTR/RTL | No unreviewed diffs |
| Accessibility | axe-core in E2E and Storybook | WCAG 2.2 AA on all pages | Zero serious/critical |
| Performance | k6 + seeded dataset; Lighthouse CI | API budgets, page budgets, query plans | Budgets in docs/01 section 8 |
| Security | Dependency/secret/SAST scans, ZAP baseline on staging | | No high findings open |
| Migration | Apply all migrations from empty and from previous release snapshot | Roll-forward only | Green on every PR |

## 2. Reconciliation (invariant) tests - run in CI on seeded data and nightly in staging

1. Milk: `sum(milk_records.litres)` = batched + discarded + home use + unbatched, per day and per month.
2. Sales: `sum(sale_lines)` = `sum(sales.total)`; invoice totals = line sums; `customer_ledger` balance = invoices - payments.
3. Stock: `batch.qty_on_hand` = `sum(stock_movements)`; no negative stock unless allowed.
4. Cost: allocated cost across animals = total period costs (within rounding rule: remainder assigned to the largest share).
5. Finance: category totals = P&L totals; account balances = opening + transactions.
6. Herd: animal counts by status = event-derived counts.
7. Payroll: payslip net = gross - deductions - advance recovery.

## 3. Critical E2E flows (must be green to release)

1. Sign up -> create farm -> setup wizard -> invite worker -> worker logs in with PIN on mobile.
2. Add animals (single, CSV import with errors) -> group them -> print QR labels -> scan opens profile.
3. Record milk (web and offline mobile) -> sync -> totals correct -> duplicate prevented.
4. Treat animal with withdrawal drug -> milk hold created -> milk entry flagged -> sale blocked -> hold expires -> allowed.
5. Create customer + price list -> sell milk -> invoice -> partial payment -> ledger statement -> WhatsApp share.
6. Heat -> insemination -> pregnancy check -> calving creates calf -> alerts and tasks appear at right dates.
7. Purchase feed -> goods receipt -> ration -> feeding log -> stock decreases -> cost per liter updates.
8. Payroll run: attendance -> payslips -> advance recovery.
9. Role restrictions: worker cannot open finance; custom role grants exactly the chosen permissions.
10. Plan limit: adding animal beyond limit shows clear upgrade message; existing data unaffected.
11. Language switch to Urdu: layout mirrors, numbers/dates formatted, no clipped text.
12. Session expiry, token reuse, logout everywhere.

## 4. Test data

- Factories in `packages/db/test` build valid graphs (farm -> users -> animals -> records).
- Seed generator: demo farm (small, realistic) and `--large` (100 farms x 500 animals x 2 years of milk) for performance.
- Fixed clock and timezone helpers (Asia/Karachi, UTC, a DST zone) to test business-date logic.
- Never use production data in tests.

### Test accounts (for manual browser checks and E2E)

- The seed script (`pnpm db:seed`) creates one demo farm with one user per system role (Owner, Manager, Vet, Accountant, Supervisor, Worker, Read-only), a Worker with a PIN and registered device, and a second farm for cross-tenant checks.
- Credentials are fake, generated by the seed, and recorded only in the seed/example-config files (never in chat, logs, docs, or commits of real secrets). Passwords differ per role; 2FA is enabled on one Owner for 2FA tests.
- Allowed only on local dev and on staging. Never created or used on production. Never reuse a real person's password.
- Outbound providers (email, SMS, WhatsApp, push, payments) run in sandbox/fake mode in these environments.
- Staging data is anonymised seed data on a Neon branch; it can be reset at any time.

## 5. Definition of Done for tests

- New code includes tests at the right level; bug fixes start with a failing regression test.
- No `skip`/`only` merged; flaky tests are fixed or quarantined within 48 hours with an issue.
- Coverage may not decrease on `domain`, `contracts`, API services.
- CI stages (parallel where possible): lint + typecheck -> unit -> integration + leak suite -> build -> E2E -> perf smoke -> scans.

## 6. Release gates

- Zero open P1/P2 bugs. P3 reviewed.
- All E2E and reconciliation tests green on staging with the production build.
- Manual exploratory pass per phase using a written charter (new farm, 10-minute tasks per role).
- Pilot farms: weekly bug triage; GA only after 4 consecutive weeks with no data-integrity defects.
