Status: in progress (slices 1 and 2 done 2026-10-24; slice 3 remaining)
Phase: 0 · Depends on: E0.1

## Goal
Every screen can be assembled from shared, accessible, tokenised components that already handle all states, light/dark and RTL.

## Notes / decisions made while working
- The Tailwind mapping uses `@theme inline` with the same names as tokens.css. Tailwind emits self-referencing declarations in its theme layer; they are overridden because tokens.css is unlayered. Do not move tokens.css into a layer.
- UI components are client components (the barrel has `'use client'`) because they use i18n hooks.
- Avoid `text-md`: tailwind-merge does not know it. Use `text-base`.
- Urdu strings are first drafts (docs/16 O11).
- Found and fixed during review: the phone top bar overflowed; language and theme now live in the user menu below the `sm` breakpoint.
- DataTable: numbers sort largest-first on the first click (TanStack default), then flip.
- Test helper `renderWithI18n` uses a wrapper so `rerender` keeps the i18n provider.
- Found by tests: the table loading skeleton was not announced to screen readers; now wrapped in `SkeletonRegion`.
