# Engineering Conventions

## 1. TypeScript and code style

- `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`. No `any` (use `unknown` + narrowing); no `@ts-ignore` (use `@ts-expect-error` with a reason).
- ESLint (typescript-eslint strict, import ordering, unicorn subset, jsx-a11y, custom rules: no hard-coded colors/strings, no direct `fetch` outside api-client, no `left/right` CSS), Prettier, EditorConfig. Pre-commit via lint-staged; CI is the gate.
- Files kebab-case (`milk-record.service.ts`); types/classes PascalCase; functions/vars camelCase; constants UPPER_SNAKE; React components PascalCase files for components.
- Prefer pure functions and small modules (< ~300 lines). Co-locate tests (`*.test.ts`). Named exports; no default exports except Next.js pages.
- Errors: throw typed domain errors (`DomainError(code, params)`); never throw strings. Map to problem+json at the edge.
- Comments explain why, not what. Public package APIs documented with TSDoc.

## 2. Module boundaries

- `domain` imports nothing from frameworks/DB. `contracts` is leaf-level. `db` depends on `contracts`. Apps depend on packages, never on each other. Enforce with dependency-cruiser in CI.
- API structure per module (NestJS): `*.controller.ts` (HTTP only), `*.service.ts` (orchestration, transactions), `*.repository.ts` (SQL), `*.dto.ts` re-exporting contracts, `*.policy.ts` (permission/scope logic). No SQL in controllers; no HTTP in services.
- Web: feature folders (`features/milk/...`) with `components`, `hooks`, `queries`, `routes`; shared UI only from `packages/ui`.

## 3. API conventions (see docs/01 section 6)

- Plural kebab resource paths, nouns not verbs; actions as sub-resources (`POST /v1/invoices/:id/void`).
- Status codes: 200/201/204, 400 validation, 401, 403, 404, 409 conflict/stale, 422 business-rule violation, 429, 5xx.
- Every mutating endpoint: permission, validation, transaction, audit, idempotency where money/stock is touched.
- Pagination: cursor; max 100; stable sort with tie-breaker `id`.
- Dates in ISO 8601 (`date` for business dates, `date-time` UTC for instants); decimals as strings in JSON for money/quantities to avoid float loss (contracts parse to decimal type on the client).
- Breaking changes require a new version or additive migration; deprecate with `Sunset` header and docs.

## 4. Database conventions (see docs/03)

- Migration files `YYYYMMDDHHmm__description.sql` (SQL-first, reviewed), generated by Drizzle then hand-checked; each includes RLS, indexes, and rollback notes.
- Naming: tables plural snake_case; PK `id`; FK `<entity>_id`; indexes `ix_<table>__<cols>`; unique `ux_`; checks `ck_`; FKs `fk_`.
- Add indexes with `CREATE INDEX CONCURRENTLY` (outside transaction) on existing large tables.
- No `SELECT *` in application queries; select explicit columns. No unbounded queries.
- Long transactions avoided (< 1 s typical); locks reviewed for migrations (`lock_timeout`, `statement_timeout`).
- Rollups/materialized views have refresh jobs, indexes, and owner tests.

## 5. Frontend conventions

- Server components by default (Next.js); client components only where interactivity needed.
- Data fetching via generated api-client + TanStack Query (query keys factory per module; stale times by data type). Mutations with optimistic updates only where safe and with rollback.
- Forms: TanStack Form + Zod from `contracts`; shared field components; error mapping from problem+json `errors[]` to fields.
- Styling: Tailwind utilities mapped to tokens; no inline hex; component variants via `cva`; no global CSS beyond tokens/reset.
- Accessibility: semantic HTML, labels, focus management in dialogs, keyboard shortcuts documented, `aria-live` for toasts.
- Performance: route-level code splitting, image optimization, virtualization for long lists, chart lazy-loading, no layout shift (reserve skeleton sizes).

## 6. Mobile conventions

- Expo with TypeScript; navigation via Expo Router; shared hooks and contracts with web; UI primitives built on the same tokens (`tokens.native.ts`).
- All writes go through the local DB + outbox layer (never call write APIs directly from screens).
- Large lists use FlashList; images cached; avoid re-renders via selectors.
- Test on low-end Android (2-3 GB RAM) and small screens (360 dp); minimum OS targets: Android 8+, iOS 15+.

## 7. Git and review

- Conventional Commits: `feat(scope): ...`, `fix`, `refactor`, `perf`, `test`, `docs`, `chore`, `ci`, `build`. Scope = module or package.
- Small PRs (< ~400 lines changed where possible). PR template: what/why, screenshots (light/dark, LTR/RTL), test evidence, DoD checklist, migration notes, risk/rollback.
- Review checklist: tenancy/RLS, permission, validation, error messages, states (loading/empty/error/success), i18n, a11y, performance (queries/indexes), tests, docs updated.
- Squash merge to `main`; version via changesets; changelog generated.

## 8. Logging and errors

- Log levels: error (needs action), warn (unexpected but handled), info (business events), debug (off in prod). Never log secrets, tokens, full bodies with PII.
- User-facing error messages come from i18n by `code`; unexpected errors show generic message + request id.
- Sentry breadcrumbs include route, farm id (hashed), and release; PII scrubbing enabled.

## 9. Dependencies

- Prefer well-maintained, popular, permissively licensed libraries; check bundle size, maintenance, security history before adding. Record non-trivial additions in docs/15 (ADR).
- Use latest stable versions at the time of adding; upgrade via Renovate PRs with full CI.
- Avoid duplicates (one date lib: `date-fns` + `Intl`; one validation: Zod; one chart lib: ECharts).

## 10. Documentation

- Docs live in `docs/`; update with code. ADR for any decision affecting stack, data model, security, or conventions. README per package with purpose, usage, and commands.
- Storybook is the living UI documentation; OpenAPI is the API reference.
